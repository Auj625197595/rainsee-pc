# 杀毒软件误报与代码签名

## 背景

打包出的 NSIS 安装包（`*.exe`）会被部分杀毒软件报 `Trojan.Win32.Generic`。

这**不是真的带毒**，而是**泛型启发式误报**（generic heuristic）：杀毒软件没有匹配到某个已知病毒的特征码，而是根据「未签名 + NSIS 安装器 + asar 里的某些字符串模式」猜测它「像」木马。所有未签名的 Electron 安装包都会不同程度地遇到这个问题。

> 结论先放这里：**未签名的安装包无法 100% 消除误报**。最有效的免费做法是「向杀软厂商提报误报样本」（通常 24–48 小时内更新）；彻底消除唯有日后上代码签名。

## 已做的代码层优化

本项目已针对 asar 内最刺眼的启发式特征做了优化（功能均不变）：

| 位置 | 优化 |
| --- | --- |
| `src/main/view.ts` `callPotPlayer` | 调起 PotPlayer 由 shell 拼接的 `exec` 改为 `execFile` 传 argv，消除命令注入漏洞 + 「浏览器进程派生 cmd.exe」特征 |
| `src/vendor/.../tts.ts` | TTS 朗读文本不再拼进 PowerShell 命令行，改为固定脚本 + stdin 传参 |
| `src/main/ai-panel/ai-protocol.ts` | `aihelp://injectJs` 注入远程脚本加了「https + 自家域名」白名单，封堵任意远程代码执行 |
| `src/main/services/auto-updater.ts` | 自动更新下载改为显式 `downloadUpdate()`，不再 `autoDownload` 静默拉取 |
| `src/main/windows/app.ts` | 删除未使用的 `exec` import，减少静态扫描噪声 |

## 最有效：向杀软厂商提报误报（免费）

把安装包作为「误报样本」提交给各厂商，他们核实后会更新签名库，通常 1–2 天后该包就不再被报。这是个人开发者最该做、性价比最高的一步。

提交前建议先在 **VirusTotal** 上传一次，看是哪几家报毒、报的名字，做到心里有数。

### VirusTotal（多引擎检测 + 样本分发）
- 地址：<https://www.virustotal.com>
- 上传安装包 → 查看几十个引擎的检测结果。
- 上传后样本会自动分发给各杀软厂商，本身就是提报的一部分。
- 建议同时上传「**未压缩的主程序 exe**」（`dist/win-unpacked/雨见浏览器.exe`）和「**安装包 exe**」，因为两者被扫的特征点不同。

### Microsoft Defender（Windows 自带，最常见的报毒来源）
- 误报提报入口：<https://www.microsoft.com/en-us/wdsi/filesubmission>
- 选「I want to report a false positive」→ 上传安装包 → 填写说明（软件名、官网、被报为 `Trojan:Win32/Generic` 等）。
- 微软通常 24–48 小时内更新 Defender 签名，全网 Windows 随之生效。**这一步能解决绝大多数 Windows 用户的报毒。**

### 360 / 火绒 / 腾讯电脑管家 / Kaspersky
- **360**：360 安全卫士 → 设置里的「软件排除/误报反馈」，或 360 软件开放平台提交白名单申请（搜索「360 误报申诉」）。
- **火绒**：火绒安全论坛（bbs.huorong.cn）误报反馈板块发帖，或邮件反馈；火绒响应通常很快。
- **腾讯电脑管家**：腾讯安全 反馈中心提交误报样本。
- **Kaspersky**：VirusDesk <https://virusdesk.kaspersky.com>，免费检测并提报。
- 各入口可能调整，以官网当前公布的「误报反馈/样本上报」渠道为准。

> 提报是「按文件（哈希）」生效的——**每次重新打包后哈希变化，需要重新提报**。所以建议：稳定版本发布后提报一次；频繁的 nightly 不必每个都提。

## 备选：绿色版 zip

本项目每次打包会同时产出 zip 绿色版（`dist/雨见浏览器电脑版-*.zip`），解压即用。

zip 版**不含 NSIS 安装器**（没有安装时的注册表写入、自解压等逻辑），启发式误报率显著低于安装包。若用户遇到安装包报毒，推荐其改用 zip 版。

## 治本：代码签名

代码签名是彻底消除误报的唯一方式。签名后的安装包会带上数字证书，杀软会基于「证书签发者」而非「启发式猜测」来判断信任。

### 三种状态对比

| 状态 | 成本 | 效果 |
| --- | --- | --- |
| 无签名（现状） | 0 | 启发式误报频繁，无法根除 |
| OV（标准）证书 | ~$200–400/年 | 大幅降低误报；但 SmartScreen 信誉需靠装机量逐步积累，初期仍可能拦截 |
| EV（扩展验证）证书 | ~$300–700/年 | 装上即被 SmartScreen 和绝大多数杀软信任，无需积累信誉；但申请需企业身份 + 硬件 token |

> 自 2023-06 起，行业要求代码签名证书的私钥必须保存在硬件 token（U 盘式 HSM）中，OV/EV 均如此。

### 个人开发者的低成本方案：Azure Trusted Signing

如果不具备企业身份、嫌 OV/EV 贵，推荐 **Azure Trusted Signing**（原 Azure Code Signing）：

- 微托管的云代码签名服务，按月订阅（约 $9.99/月），个人开发者也能申请。
- 无需自己保管硬件 token，签名在云端完成。
- 签名的 exe 会逐渐积累 SmartScreen 信誉（不如 EV 立竿见影，但远好于无签名）。
- electron-builder 原生支持（`win.signingHashAlgorithms` + Trusted Signing 配置，详见 electron-builder 文档的「Azure Trusted Signing」一节）。

### 接入 electron-builder（拿到证书后）

配置 `electron-builder.json` 的 `win` 段，三选一：

```jsonc
{
  "win": {
    // 方式 A：直接指定证书文件（pfx）+ 密码
    "certificateFile": "private/cert.pfx",
    "certificatePassword": "xxx",
    // 或方式 B：按主题名/SHA-1 从证书库取
    // "certificateSubjectName": "CN=Rainsee...",
    // 或方式 C：用环境变量（CI 友好，不落盘）
    // 设置 CSC_LINK（pfx 的 base64）和 CSC_KEY_PASSWORD
    "signtoolOptions": {
      "additionalCertificateFile": ""
    }
  }
}
```

CI 环境推荐方式 C：在 GitHub Secrets 存 `CSC_LINK`（`base64 cert.pfx`）和 `CSC_KEY_PASSWORD`，electron-builder 会自动识别并签名，私钥不进仓库。

签名后用 `Get-AuthenticodeSignature 你的安装包.exe`（PowerShell）确认 `Status` 为 `Valid`、`SignerCertificate` 非空，即签名成功。
