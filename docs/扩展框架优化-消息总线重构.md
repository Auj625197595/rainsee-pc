# 扩展框架优化：消息总线与 content script 投递重构

> 对应未提交工作区改动（20 个文件，+1302 / −2060，净减约 758 行）。
> 范围：`src/vendor/electron-chrome-extensions/**`、`src/main/extension-storage-patch.ts`、`src/main/sessions-service.ts`、`src/preloads/view-preload.ts`。

## 一句话概述

把扩展消息总线从「只发主帧 + 单通道 + 各处打地鼠式去重/兜底」升级为「**精确 frame 定向 + 声明式/动态脚本双通道自动路由 + popup 作为一等发送方**」的统一架构，同时把源码级 SHIM 从一堆针对单个扩展的专用补丁收敛为一层通用兜底层，并清掉了几乎全部临时诊断日志。

## 主题一：content script 消息的精确 frame 定向 + 双通道自动路由（核心）

### 动机
旧实现 [`messaging.ts`](../src/vendor/electron-chrome-extensions/browser/api/messaging.ts) `sendMessageToTab` 只把消息发到 `tab.mainFrame`、只走 `crx-cs-message` 一个通道。但内容脚本可能存在于：
- **动态注入的脚本**（`chrome.scripting` / `chrome.userScripts`，注入到 ISOLATED 或 MAIN world，由 [content-bridge.ts](../src/vendor/electron-chrome-extensions/browser/api/content-bridge.ts) 桥接）；
- **manifest 声明式 `content_scripts`**（Electron 原生注入到扩展 ISOLATED world）。

两者运行在不同 world、监听不同通道。发到主帧 + 单通道会导致其中一类脚本永远收不到消息。又因为渲染层此前是「native + IPC 双路径」并发，一条扩展调用会被派发两次，只能靠 `csSendDedup`（150ms 窗口）和 view-preload 的 `__crxDedup`（dessant 400ms 窗口）在接收端打地鼠去重。

### 改动

**1. 动态脚本注册表 [`DynamicContentScriptRegistry`](../src/vendor/electron-chrome-extensions/browser/context.ts)**
- 接口：`token / mark / clearExtension / clearFrame / has`。
- 实现 [`createDynamicContentScriptRegistry`](../src/vendor/electron-chrome-extensions/browser/index.ts)：`WeakMap<frame, Map<extId, epoch>>`。
- **epoch 机制**：扩展卸载/重载时 `clearExtension` 递增该扩展的 epoch，旧标记自动失效；**frame token**：导航时 `clearFrame` 递增 frame token，防止「注入中 frame 已导航」的竞态。
- 注入方登记：
  - [scripting.ts](../src/vendor/electron-chrome-extensions/browser/api/scripting.ts) 注入成功回调里 `mark(extId, frame, registryToken)`（MAIN world 脚本不登记），扩展卸载时 `clearExtension`。
  - [user-scripts.ts](../src/vendor/electron-chrome-extensions/browser/api/user-scripts.ts) 同样登记/清理。
- 生命周期观察 [`observeDynamicContentScriptFrames`](../src/vendor/electron-chrome-extensions/browser/index.ts)：tab 监听 `did-start-navigation`（非就地导航即 `clearFrame`）与 `destroyed`。

**2. `sendMessageToTab` 重写**（[messaging.ts](../src/vendor/electron-chrome-extensions/browser/api/messaging.ts)）
- `tabId` 改为 `number | undefined`（支持「当前标签」语义），用 `resolveTabForSender` 解析。
- `framesForTab` / `findFrameForTab`：按 `options.frameId` 精确定位单帧，否则枚举 `mainFrame.framesInSubtree` 全部子帧。
- 对每个目标 frame 判断该走哪条通道：
  - `dynamicContentScripts.has(extId, frame)` → `crx-dynamic-cs-message`
  - `frameMatchesManifestContentScript(extension, frame)`（按 manifest `content_scripts` 的 `matches`/`exclude_matches`/`all_frames` 匹配）→ `crx-cs-message`
- 多帧/多通道并行投递，**首个非 `undefined` 响应胜出**，全部 5s 超时。
- 删除 `csSendDedup` 及其 150ms 去重逻辑。

**3. 动态脚本接收端 [content-bridge.ts](../src/vendor/electron-chrome-extensions/browser/api/content-bridge.ts)**
- 监听通道 `crx-cs-message` → **`crx-dynamic-cs-message`**。
- `_emit` 从「只返回最后一个非 undefined」改为**返回全部 listener 结果数组**；调用方据此识别 `return true` / Promise / 同步值，正确驱动异步 `sendResponse`，并补 30s 安全网。
- 补 `hasListeners()`。

**4. 渲染层单路径化 [renderer/index.ts](../src/vendor/electron-chrome-extensions/renderer/index.ts)**
- `tabs.sendMessage` 由「native + IPC 并发取首响应」改为**纯 IPC 单路径**（`electron.invokeExtension(..., 'tabs.sendMessage', ...)`），从源头消除重复派发，使主进程侧的去重不再必要。

**5. 页面侧接收/响应闭环 [view-preload.ts](../src/preloads/view-preload.ts)**
- 删除 `__crxDedup` 与 dessant 词汇表 `DSS_IDS` 去重（主进程已精确路由，不再重复投递）。
- `crx-cs-message` → `__crxCsFwd` 转发时携带 `extensionId`，供隔离世界按扩展过滤。
- 新增 `__crxCsFwdResp` 处理：隔离世界 SHIM 桥的响应经 `window.postMessage` 回到主世界 preload，再以 `crx-cs-message-response` IPC 回送 main，完成响应闭环（供声明式脚本路径）。

> 相关历史记忆：`tabs.sendMessage` 双路径重复派发、dessant view-iframe port bridge。

## 主题二：popup / 扩展页面作为「一等发送方」

### 动机
action popup / options 是扩展页面，Electron 把 popup 放在独立子 `BrowserWindow` 里。当 popup 调 `tabs.query({active:true, currentWindow:true})` 或不带 tabId 的 `tabs.sendMessage()` 时，「currentWindow」会被解析到 popup 自己的窗口（没有标签），而不是拥有活跃标签的父浏览器窗口；popup 还常持有「陈旧 tabId」（打开时记下的 tab 已切换）。

### 改动

**1. currentWindow 按 sender 解析**（[store.ts](../src/vendor/electron-chrome-extensions/browser/store.ts)）
- 新增 [`getWindowFromEvent(event)`](../src/vendor/electron-chrome-extensions/browser/store.ts)：sender 若是被 track 的标签 → 取其窗口；否则 `BrowserWindow.fromWebContents` → 若不在已 track 窗口集，则取 `getParentWindow()` 指向的父浏览器窗口。
- `getCurrentWindow(event)` / `getActiveTabOfCurrentWindow(event)` 透传 event。

**2. tab 解析回退**（[messaging.ts](../src/vendor/electron-chrome-extensions/browser/api/messaging.ts)）
- `resolveTabForSender`：tabId 找不到时，若判断 sender 是「未被 track 的扩展页面」（`isUntrackedExtensionPageSender`）或消息是 popup→content（`isPopupAuthoredContentMessage`，`from:'popup:*' to:'content:*'`），则回退到 `activeTabForPopupSender`（父窗口活跃 tab）。

**3. tabs/windows API 全面透传 event**
- [tabs.ts](../src/vendor/electron-chrome-extensions/browser/api/tabs.ts)：`query` **真正实现** `currentWindow`/`lastFocusedWindow` 过滤（原先被注释掉）；`getAllInWindow`、`reload`、`goBack/goForward`、`captureVisibleTab`、`detectLanguage`、zoom 系列全部改用 `getActiveTabOfCurrentWindow(event)` / `getCurrentWindow(event)`。
- [windows.ts](../src/vendor/electron-chrome-extensions/browser/api/windows.ts)：新增独立的 `getCurrent`（走 `getCurrentWindow(event)`，不再等于 `getLastFocused`）；`get/update/remove` 的 `WINDOW_ID_CURRENT` 也走 event。

**4. popup 自身的 tab 兜底**（[renderer/index.ts](../src/vendor/electron-chrome-extensions/renderer/index.ts)）
- `tabs.query` / `tabs.getCurrent` 包一层 `withInjectedTabsFallback`：native 返回空时，从 `window.__crxTabs` / `localStorage['__crxTabs_lsinjected']` / `location.hash` 的 `crxbridge=` 注入快照回退读取。
- `normalizePopupTabId`：popup 持有的 tabId 若不在注入快照里，归一化为当前活跃 tabId。
- `tabs.connect` 抽出 `fallbackTabConnect`，复用归一化与 frameId 透传。

**5. popup preload 兜底**（[popup.ts](../src/vendor/electron-chrome-extensions/browser/popup.ts)）
- `webPreferences.preload` 显式指定 `build/crx-preload.bundle.js`：session 注册的扩展 preload 在 Electron 把 popup 与 sandboxed 扩展进程同址时会被跳过，`webPreferences.preload` 能在该路径存活且与 session preload 幂等。

## 主题三：长连接 Port 支持 popup ↔ frame 直连

[messaging.ts](../src/vendor/electron-chrome-extensions/browser/api/messaging.ts) `connectToTab`：
- 支持可选 `tabId` 与 `info.frameId`，用 `findFrameForTab` 定位目标 frame（不再写死 `mainFrame`）。
- `PortEntry` 新增 `ownerFrame`：当调用方是 popup/扩展 iframe（`senderFrameOf(event)` 存在且 ≠ 目标 frame）时记录。
- `onPortPost` / `teardownPort` / `onPortDisconnect`：entry 有 `ownerFrame` 时，消息在 `sourceFrame ↔ peer`（frame 或 ownerFrame）间**直连转发**，disconnect 两端都通知，无需经 SW 中转。

这让 `chrome.tabs.connect()` 从 popup/扩展 iframe 直达内容脚本 Port。

## 主题四：SHIM_BODY 从「打地鼠」收敛为通用层 + 命名空间健壮化

### `extension-storage-patch.ts`（1099 → 437 行）

旧的 `SHIM_BODY` 有 748 行针对单个扩展的专用补丁：手写 `chrome.proxy.settings`（为 ZeroOmega）、手写 `chrome.permissions`（为 dessant）、XHR 版 `chrome.i18n`（为 AdGuard 英文）、`crxbridge=` URL hash 桥、namespace installer、`chrome.extension` stub、tabs DEF 等。每个都带超长注释。

新 `SHIM_BODY` 收敛为 **5 个明确职责**（见文件顶部注释）：
1. 只中和 Electron 独立的 native `browser` fork，保留扩展自建的 `browser===chrome` 别名；
2. 早期 `chrome.permissions`（preload 迟到时）；
3. 声明式 content-script 接收桥（crx-preload 不在隔离世界时）；
4. popup `tabs.sendMessage` 路由；
5. `chrome.storage.sync/managed` → `local`。

外加一层**通用 generic API surface**：工厂 `AF/AM/AV/AD` 对 `tabs/windows/permissions/alarms/commands/contextMenus/cookies/bookmarks/history/downloads/notifications/topSite/idle/power/management/sessions/search/tabGroups/browsingData/action/browserAction/proxy/system` 全命名空间「**缺失才补**」，每次调用**先走 `crx-msg` IPC，失败再降级返回类型默认值**（query/get→`[]`，set/remove/create→`true`，其余 `undefined`）。

### `browser`/`chrome` 命名空间
- [renderer/index.ts](../src/vendor/electron-chrome-extensions/renderer/index.ts) `removeNativeBrowserAlias` 与 SHIM 的 browser 段统一为**关系型**：只删与 `chrome` 不同的 native `browser`；退化上下文（只有 `browser`）把 `browser` 镜像成 `chrome`。
- `ExtensionEvent` 补全 `hasListener/hasListeners/getRules/removeRules/addRules`（原先一律 `throw "Method not implemented."`），内部维护 `listeners` 数组。
- 移除 bookmarks/history/downloads/browsingData/management 等的 `shouldInject` 权限门控（改为总是注入 factory）。

> 相关历史记忆：SHIM 每文件重跑误伤扩展自带别名、crx-preload skipped → native i18n 英文、sandboxed popup native tabs 不可配置。

## 主题五：不可克隆值在 IPC 边界统一剥离

V8 结构化克隆无法跨越 `Blob/File/function/symbol/getter`，扩展把这些原样塞进 IPC 会报「could not be cloned」。
- [view-preload.ts](../src/preloads/view-preload.ts) 新增 `crxStripUncloneable`（Blob/File → `{__crxBlob/__crxFile,...}` 占位，递归剥离 function/symbol/getter），在 `crx-cs-message-response`、`crx-port-post` 多个发送点应用。
- [renderer/index.ts](../src/vendor/electron-chrome-extensions/renderer/index.ts) 的 `sendMessageResponse` / native onMessage 保留同类剥离。
- [content-bridge.ts](../src/vendor/electron-chrome-extensions/browser/api/content-bridge.ts) `_emit` 返回数组配合 `await Promise`，让 MV3 异步响应能正确回传。

> 相关历史记忆：Electron IPC can't clone Blob（dessant 图片存储请求两层修复）。

## 主题六：卸载扩展彻底清理存储（[sessions-service.ts](../src/main/sessions-service.ts)）

新增 `cleanupExtensionData(id)`，仅在 `uninstallExtension`（`removeExtension` 之后）调用：
1. 删 `chrome.storage.local/sync/managed` 的 LevelDB 子目录 `Partitions/view/{Local|Sync|Managed} Extension Settings/<id>`（`clearStorageData` 清不掉扩展子系统 LevelDB）；
2. `view.clearStorageData({ origin: 'chrome-extension://<id>', storages: [appcache,cookies,filesystem,indexdb,localstorage,shadercache,websql,serviceworkers,cachestorage] })`；
3. IndexedDB 残留目录兜底（`chrome-extension_<id>_0.indexeddb.*`）。

注释明确：**禁用 / 重载路径绝不调用**，否则会丢用户数据；必须在 `removeExtension` 之后调，确保 SW 已停、文件句柄已释放，Windows 上 `fs.rm` 才不会被文件锁挡住。

> 相关历史记忆：装 uBlock 必崩（storage.local LevelDB 膨胀 OOM）——本机制同样能清掉膨胀分区的扩展。

## 风险与注意事项

- **SHIM_BODY 任一语法错误会让所有扩展 JS 入口解析失败**。若改 SHIM，按既有流程：`validate-shim-source.js` → webpack → `check-bundle-shim-hash.js` → 必要时 `force-repatch-shim.js`。
- **`cleanupExtensionData` 只能由 uninstall 触发**；若未来给 disable/reload 复用，必须先确认不删数据。
- 通用 generic API surface 是「**缺失才补 + IPC 优先**」的兜底，不是另一套实现——扩展正常运行时走 vendor preload 注入的真实 API，仅在 degraded 启动（sandboxed、preload 迟到、bridge 缺失）时填充。
- 验证仍以 `npm run build`（webpack）为准；tsc / ESLint 不是可用门禁。
